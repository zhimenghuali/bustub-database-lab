## 实现要点

哈希表以哈希低位索引目录，目录中的多个指针可以共享同一个桶。先尝试更新已有键或插入；只有新键无法放入时才分裂。局部深度等于全局深度时扩容目录，随后重分配相关目录指针并移动桶节点，重复检查直到插入成功。删除不合并桶。所有表操作由同一个互斥锁保护。

LRU-K 为每个帧保存最多 K 次访问时间，逻辑时钟在持锁状态下递增。淘汰只考虑可淘汰帧，优先选择访问不足 K 次的帧；同类选择历史中最早时间最小的帧。历史已满时，最早时间就是倒数第 K 次访问时间。`Size()` 只统计可淘汰帧，重复设置状态不会重复计数；淘汰或删除会清除历史。帧编号范围是 `[0, num_frames)`，非法编号会抛出异常。保留仓库的默认 K=10。

缓冲池先使用空闲帧，再向替换器申请受害帧。脏页复用前写回磁盘，旧映射随后移除，并重置页面数据和元信息。新建或获取页面会增加固定计数、记录访问并禁止淘汰；解除固定时以逻辑或累积脏标记，计数为零后才允许淘汰。刷新操作无论脏标记和固定状态如何都写回页面。删除被固定的页面会失败；成功删除会释放帧和访问历史。

缓冲池锁保护页元信息、空闲列表及跨组件状态，持有该锁后才调用页表或替换器。页表与替换器分别使用自己的锁，不反向调用缓冲池。批量刷新使用已持锁的内部辅助函数，避免再次获取同一把锁。

## 教程纠错与版本边界

- 教程后半段将 LRU-K 描述为优先淘汰达到 K 次访问的页面，与前文、官方任务说明和仓库测试冲突。本实现优先淘汰不足 K 次访问的可淘汰帧。
- 不足 K 次访问时比较最早一次访问时间，不能简单替换成最近一次访问的 LRU 顺序。
- 页表映射方向为 `page_id → frame_id`。
- 哈希表的 `Insert` 返回 `void`；桶的 `Insert` 才返回是否成功。
- 使用仓库中的 `NewPgImp`、`FetchPgImp`、`FlushAllPgsImp` 等实际接口名称。
- 访问命中缓存时，同样需要更新固定计数和 LRU-K 历史；`FlushPage` 不能因页面仍被固定而跳过写回。

## 远程验收方法

使用 `ssh nscc-cd` 连接超算，在 CPU 分区提交单节点、单任务、4 个 CPU、30 分钟上限的作业。编译并行度固定为 4。登录节点仅用于传输、查看记录和提交作业。

工具链为 GCC 13.1、CMake 3.28.1、Clang Format/Tidy 14.0.6。原始仓库在 GCC 13 下出现第三方 fmt 的 `dangling-reference` 和原有时间类型的 `format-truncation` 警告升错。因此验收命令仅对这两个既有警告取消 `-Werror`，保留警告输出和其他错误检查；源码不因这两个兼容问题而改动。

Clang Tidy 的独立安装包没有附带基础头文件。本次补齐 LLVM 官方 14.0.6 源码中的 `clang/lib/Headers`，安装到工具对应的 `lib/clang/14.0.6/include` 资源目录；工具包和头文件来源及 SHA-256 随验收证据保存。

远程项目目录：`/yhfs/users/wenyifan/database-lab/p1-20261102-01a19a5e`。各候选版本使用独立源码目录，普通 Debug、ASan/UBSan、TSan 和干净基线复测使用独立构建目录。

```bash
# 在源码已同步为 source-<提交号> 后提交验收。
sbatch --output=evidence/accept-%j.slurm.log \
  source-<提交号>/tools/project1/submit_nscc.sbatch \
  /yhfs/users/wenyifan/database-lab/p1-20261102-01a19a5e <提交号>
```

脚本默认依次执行 Debug、规范检查、ASan/UBSan、TSan 和提交包复测，也支持在提交号后指定阶段。Debug 使用仓库默认的 AddressSanitizer，内存检查阶段额外启用 UndefinedBehaviorSanitizer；每个测试程序最多运行 300 秒。

原有测试为 29 个，新增测试为 24 个（含 B 模块 11 个 `Find`/`Remove` 边界与并发用例），总计 53 个。每个测试程序使用独立工作目录。验收同时检查退出码、XML 中的实际执行数量、失败数和跳过状态；只有调度器显示成功不构成验收通过。

提交包通过 `submit-p1` 生成，逐项检查六文件清单与源码哈希，再覆盖到原始基线并重新编译、运行原有 29 个测试。最终结果、作业编号及日志位置在交付的验收记录中列明。
